Trust should be inspectable.

The product, the enforcement layer and the development tools have distinct responsibilities.

01 · Product controls

Mandate

Preserves evidence origin, applies payment policy, requests human authority, and checks the exact action before release. This HTML simulates that flow locally; the separate MVP API implements server enforcement.

Interactive simulation
02 · Runtime evaluation

PRISM

Observe real agent runs, inspect failures, improve the system, and prove the change with a rerun. The API package includes its SDK. This standalone demonstration sends no traces.

03 · Development workflow

GIDE

The mandatory code editor or CLI is used to build, test and iterate on a substantive segment. Development session and commit evidence establish actual use. A logo or Git push does not.

What the demonstration can establish

Scope and limitations
Source independence

Copied records keep their origin. Several copies do not become independent authorization.

Exact authority

A changed beneficiary, amount or cash context requires a fresh matching approval.

Human escalation

Uncertainty creates a review request with decision points. It does not become an unsupported fraud accusation.

Routine payments

Lower-risk cases can be ready under the configured policy. The current policy still requires controller approval.

Outcome verification

The demo records one synthetic ledger effect. It does not verify settlement at a bank.

Regulatory applicability

No visual state means universally compliant. Actual obligations depend on the customer, activity and jurisdiction.
