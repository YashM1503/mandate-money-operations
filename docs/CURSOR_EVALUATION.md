# Independent evaluation — MANDATE security MVP

Date: 5 September 2026
Evaluator: Cursor sub-agent 3 (read-only). No rebuild, deploy, push, merge, publish, or sponsor configuration was performed. No listed builder-owned files were edited.

## Scope and method

Reviewed the current working tree under `mvp/` as the existing-plus-proposed implementation after the builder pass. Focus: the security questionnaire engine, connected API, offline replay, exports, honesty labels, auditor boundaries, and secret-file coverage.

Primary sources: `mandate/security.py`, `mandate/api.py` (security routes only), `static/security.html`, `tests/test_security.py`, `tests/security_browser_qa.cjs`, `docs/SECURITY_UPDATE_QA.md`, `docs/SECURITY_UI_QA.md`, `docs/QA_REPORT.md`, `README.md`, `.gitignore`, `.env.example`, `scripts/bootstrap.py`. Cross-checked payment-side honesty and citation handling in `docs/SPONSOR_SETUP.md`, `tests/test_integrations.py`, and `static/index.html` only where they affect the listed failure modes.

Method: static review plus targeted confirmation of git ignore/tracking. Python 3.12 was not available in this evaluator environment; server-behavior claims below are from source and from the assertions already written in `tests/test_security.py`. Browser connected-mode was not re-run.

Findings are limited to defects that can be shown in the current tree. Each recommended fix names an existing test or a test the lead should add. No unverifiable defects are listed.

## What already holds

Honest labels on the security surfaces reviewed: `static/security.html` entry, footer, assurance, memo, and source inspector deny live models, company certification, live PRISM/GIDE/ElevenLabs, and measured business outcomes. Demo mode is labeled as a persona, not authentication (`tests/security_browser_qa.cjs` requires `/not authentication/i`). Connected mode requires a provisioned username/password and does not invent a browser session. `README.md`, `docs/QA_REPORT.md`, `docs/SECURITY_UPDATE_QA.md`, and `docs/SPONSOR_SETUP.md` keep GIDE/PRISM/live-model gates as pending.

Fail-closed integrity on the server engine: `_valid_sources` rejects hash mismatch, unknown-id reuse with altered text, duplicates, and cycles. `_search` only supports claims from recognized fixture versions. `test_changed_source_fails_closed` and `test_source_integrity_duplicate_cycle_and_arbitrary_known_id` lock that. Content hashes are described as consistency, not truth, in `mandate/security.py`, the assurance notice, the source inspector (`Integrity ≠ truth`), and export `verification.limitation`. Browser QA requires a digest match plus an integrity/truth note.

Policy is not treated as universal enforcement: MFA stays `conflict` until `add_resolution`; “yes” / “MFA is enabled” / “everything is compliant” do not resolve it (`test_mfa_contradictions_only_resolution_fixture_resolves`, `test_prompt_injection_does_not_resolve_or_invent_sources`). Policy-only MFA exports as `unknown`.

Questions are not stored as backup assertions on the server: `test_question_is_not_employee_confirmation` (`Are backups performed daily and automated?`). Offline `localReply` has the same `?` / interrogative-prefix guard for backups.

User claims stay `user_confirmed`: complete backup and background-check answers do not become `evidence_backed` (`test_correction_memory_stays_user_confirmed`, `test_evidence_backed_vs_user_confirmed_export_includes_unknowns`). Prompt-injection strings do not invent sources.

Unknowns remain in exports: `export_questionnaire` returns all four status keys and keeps leftover unknowns (`test_followups_corrections_and_conflict`, `test_evidence_backed_vs_user_confirmed_export_includes_unknowns`, `test_export_and_resolution_do_not_mutate_caller`). Offline browser export is checked by `tests/security_browser_qa.cjs` (`Export hid unknowns`). `qa-evidence/security-export.json` still has `background_checks` as `unknown` after the scripted IAM fixture.

Human-review copy: memo and export are drafts, “no external submission,” “human review required.” There is no implemented partner-submit gate; `demo/README.md` states that absence. POST mutation is limited to `analyst` and `controller`.

Payment-side citation handling (adapter, not the security engine): `tests/test_integrations.py` `test_unknown_citation_discarded_but_actual_exchange_traced` discards invented citation IDs. Integration status keeps `gide: usage_pending` unless external evidence is recorded.

Secret files used by this app are gitignored and untracked in the MVP repo. `static/security.html` stores no password.

## GIDE handoff

Not unconditionally ready.

The server questionnaire contract (fail-closed sources, MFA conflict, user_confirmed vs evidence_backed, export of unknowns, POST-denied auditor) is in good enough shape for a reviewer to exercise. The three majors would be fair GIDE findings if left in: inspect-only is false at the GET/seal layer (E1); the primary chat surface mislabels every user turn as an employee assertion (E2); offline replay still disagrees with the server on `restore` and ordinary `ignore` sentences (E3).

Do not copy `data/` (signing key, password hashes, SQLite, `demo-credentials.txt`) into a GIDE workspace. Hand the git-tracked tree only. Do not describe the tree as live-AI, live-PRISM, certified, or production-ready.
